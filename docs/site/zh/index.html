产品能力

覆盖支付全链路。

本项目参考开源项目 AgPayPlus 的完整业务场景与设计理念，再从零重新建模。 它不是代码迁移，不是版本升级，也不是对旧系统的重构。

01

商户管理

商户进件、应用接入、费率配置、权限与经营统计，支撑 ISV / 代理商 / 商户三级体系。

02

多渠道交易

下单、收银台交互、渠道路由与回调处理，由显式的订单状态机驱动。

03

退款

退款记录作为独立聚合，配套渠道退款回调与幂等重试处理。

04

分账结算

接收方绑定、分账规则配置、自动分账与代理商资金结算。

05

转账与通知

资金转账，以及通过事件总线可靠投递的异步商户通知。

06

对账

渠道账单导入、差异检测与周期清算，由分布式任务服务调度执行。

领域边界

四个服务，四个领域。

每个服务继承旧系统成熟的业务边界，再按同一套四层 DDD 规范重建。 业务服务不承载任何认证逻辑 —— 认证全部收敛在网关层。

PAYMENTSERVICE

支付核心域

下单、渠道支付、回调解析、状态机流转、退款业务与支付通知调度。

MERCHANTSERVICE

商户域

商户进件、档案管理、应用接入、费率配置、权限管理与经营数据统计。

AGENTSERVICE

代理商分润域

代理商层级体系、分润规则、收益统计、自动分账与代理商资金账务。

MANAGERSERVICE

平台管理域

平台级配置、支付渠道管理、支付参数、全局订单管理与风控参数配置。

设计思想

架构保证的六件事。

01

领域层零外部依赖

聚合根、值对象、领域事件与规约都是纯业务逻辑。资金规则与状态机与数据库、 中间件完全解耦，因此可以独立测试。

02

CQRS 读写分离

高并发交易写入与高频订单查询分离，化解支付场景固有的性能冲突。

03

事件驱动解耦

PaymentSucceededEvent 发布到 RabbitMQ 事件总线，下游服务异步消费， 服务之间没有硬编码依赖。

04

网关中心化的安全架构

OpenIddict 只负责签发令牌。YARP 做无状态的 JWT 公钥验签、接口签名校验与权限验证， 业务服务完全看不到认证代码。

05

金额精确处理

金额用整数分表示，费率用定点小数。二进制浮点数绝不参与任何资金计算。

06

默认云原生

独立 Docker 镜像、无状态部署、GitHub Actions 交付，当前跑在 K3s， 未来可无缝演进到标准 Kubernetes。

共享底座

复用，而不是重造。

基础设施放在同组织的独立仓库与自研 NuGet 包中，所有服务开箱即用地继承同一套规范。
