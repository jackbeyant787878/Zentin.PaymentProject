分层组件与服务说明

1. 前端层（外部流量入口）

面向商户、运营人员与渠道代理商的客户端应用。只允许 HTTPS 外部请求，不能直接访问内网资源。

  • 桌面后台：日常对账、费率配置、渠道管理
  • 移动端与 H5 收银台：终端用户创建支付订单、查询订单状态
  • 第三方支付网关：微信 / 支付宝 / 银行的异步 Webhook 回调

2. 网关层（唯一公网边界）

所有外部流量在此汇聚，完成安全校验、请求路由与流量治理。后端微服务全部与公网隔离。

  • Nginx：四层负载均衡、SSL 证书卸载、静态资源转发
  • YARP .NET 10 网关：JWT 鉴权、动态服务发现、熔断限流、全链路日志追踪。通过内网标准 RESTful HTTP 与内部微服务通信。

3. 应用层（核心业务微服务）

按领域驱动设计划分业务域，用 CQRS 做读写分离，承载商户、交易与分账核心逻辑。

  • IdentityService：基于 OpenIddict 的集中式认证与细粒度权限控制
  • SchedulerService：基于 Quartz.NET 的分布式任务调度，负责自动对账、退款执行、超时关单
  • 四个领域微服务：运营平台、渠道代理商、商户控制台、支付网关

4. 基础设施层（分布式中间件底座）

共享中间件与公共组件，把业务逻辑与分布式能力实现解耦。

  • Consul：服务注册、健康检查与分布式 KV 配置中心
  • RabbitMQ：异步事件队列，用于削峰、系统解耦与事务消息
  • 公共能力：监控、邮件通知、容器运行时、服务治理与集中式日志

5. 存储层（持久化、缓存与日志数仓）

  • SQL Server：核心订单、商户档案与分账结算记录的 ACID 事务存储
  • Redis：分布式锁、热点数据缓存、会话与限流计数器
  • ELK 日志栈：全量 API 请求日志与异常日志存储，故障排查时快速检索

6. 支撑层（云运行时底座）

容器集群运行所需的底层计算、网络与安全资源，以及内网隔离保护。

7. CI/CD DevOps 流水线（自动化构建与部署）

从源码提交到生产集群部署的全自动流程，支持一键回滚做版本恢复。

端到端支付请求流程

以商户标准支付下单为例，完整的客户端到存储请求链路：

步骤 1　客户端发起外部 HTTPS 请求

商户 H5 / 桌面后台通过公网 HTTPS 发送下单请求，流量进入公网 Nginx 集群入口。

步骤 2　Nginx 负载均衡转发

Nginx 完成 SSL 解密，按权重规则把入站流量分发到健康的 YARP 网关实例。

步骤 3　YARP 网关统一前置处理

1. 校验 JWT 会话令牌与接口访问权限；2. 验证请求签名防篡改；3. 从 Consul 拉取最新健康服务列表；4. 对下游服务执行限流与熔断保护；5. 生成全局 TraceId 用于全链路日志追踪。

步骤 4　内网 RESTful HTTP 调用支付微服务

网关通过 K8s 内网 ClusterIP 向 PaymentService 发起 RESTful HTTP 请求，所有业务服务与公网隔离。

步骤 5　业务服务读写处理

1. 从 Redis 缓存读取商户费率配置；2. 构造订单领域实体；3. 在本地数据库事务中持久化新订单；4. 向 RabbitMQ 发布「待支付」领域事件。

步骤 6　异步中间件消费与日志落库

RabbitMQ 消费者异步发送支付通知邮件、预处理日对账数据；Filebeat 采集全部请求日志并投递到 ELK 存储集群。

步骤 7　同步响应返回客户端

支付收银台链接与唯一订单号沿完整请求链路回传前端，同步请求生命周期结束。

步骤 8　异步渠道回调收尾（支付完成后）

终端用户完成支付后，微信 / 银行服务端向网关发送异步 Webhook 回调。网关重新校验回调签名，更新订单支付状态，生成分账结算数据并推送用户支付通知。

容错与韧性机制

  • 不健康实例剔除：Consul 健康检查摘除下线实例，YARP 自动把流量路由到健康节点。
  • 流量突增保护：YARP 限流 + RabbitMQ 峰值缓冲，避免数据库过载。
  • 消息不丢：RabbitMQ 持久化队列 + 死信队列，配合定时重试补偿任务。
  • 分布式排障：通过 TraceId 在 ELK 日志存储中交叉检索，实现全链路可追溯。
