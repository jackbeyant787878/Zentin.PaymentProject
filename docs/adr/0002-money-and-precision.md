# ADR-0002 · 金额用 long（分），费率用 decimal(20,6)

- 状态：已采纳
- 日期：2026-11-08

## 背景

金额精度直接关系资金正确性。可选方案：

1. 全部用 `decimal`
2. 金额用 `long`（最小货币单位，分），费率用 `decimal`
3. 用 `double`

供体 agpayplus 与 Zentin 现有代码、现有 EF 配置、DTO、渠道报文字段全部采用方案 2。

## 决策

- 金额一律 `long`，单位：分。字段名统一 `Amount` / `PayAmount` / `RefundAmount` / `MchFeeAmount` 等，含义固定为分。
- 费率一律 `decimal`，`HasPrecision(20, 6)`。
- 禁止 `double` / `float` 参与任何金额或费率计算。
- 元/分转换只允许发生在 API 边界与渠道适配器边界，并且必须有测试。

## 后果

好处：

- 与供体和现有代码零摩擦，不需要批量改造 34 个实体、22 个仓储和 15 个渠道。
- 整数运算无浮点误差，适合做幂等与对账。
- EF 映射简单（`bigint`）。

代价与约束：

- 可读性差（`10000` 是 100 元），必须在字段注释或契约文档里写明单位。
- 前端与外部对接方容易误传元，需要在 API 边界做显式校验与转换。
- 汇率、多币种小数位不同的场景目前不支持；`Currency` 字段保留但只支持 `CNY` 语义。

## 替代方案

- **decimal 金额**：可读性好，但要改动全部现有配置与渠道字段，且无法消除"元/分混用"风险，只是转移了风险。
- **double**：绝对禁止，浮点误差会导致对账永远不平。
